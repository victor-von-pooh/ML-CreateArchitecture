# 設計

ML-CreateArchitecture の設計の方針をまとめる.

## 目的

ML-ModelControl の部品を GUI で並べてつなぎ, モデルを組み立てるローカルの Web アプリ.
コードを書かずに, 部品の一覧から選んで置き, 線でつなぎ, 引数をフォームで決め, 形とパラメータ数を確かめながらモデルの定義を作る.

- モデルの定義 (YAML か JSON) の読み書き, 確認, 形の推定, 組み立ては全て ML-ModelControl が行う. このアプリは画面と, 定義のファイルの置き場だけを受け持つ
- ML-ModelControl は submodule にする (ML-Dashboard と ML-Found の関係と同じ)
- 今は独立したアプリ. 将来は ML-Found と ML-Dashboard と合わせて, 1 つのアプリに統合することを目指す

## 全体の中での役割

「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「モデルの作成・選定」の段階で画面を受け持つ. ライブラリは ML-ModelControl.

- 定義のファイルの形は決めない. 読み書きするのは ML-ModelControl の定義の形だけで, その形が他の段階 (学習など) との約束になる
- 他の段階の画面と 1 つのアプリにまとめた後の定義の置き場と, 学習のプロジェクトとの結び方は未定

## 構成

| 部分 | 中身 |
| --- | --- |
| バックエンド | Python, FastAPI. ML-ModelControl を呼ぶ API と, 定義のファイルの一覧, 読み込み, 保存 |
| 画面 | TypeScript, React, Vite. グラフの編集に React Flow (`@xyflow/react`) を使う |

ML-Dashboard と同じ構成と道具 (uv, pnpm, Ruff, mypy, Prettier, oxlint, OpenAPI から画面の型を作る) にそろえ, 将来の統合を楽にする.

## 画面

1. **部品の一覧** (左): 出どころごとに並べ, 名前と説明で検索する. 使えない部品 (ライブラリが無いものなど) は理由付きで選べない状態にする. 押すと見えている範囲 (か選んでいるものの右) に置き, キャンバスにドラッグすると落とした位置に置く (ドラッグでは線を引かない). 検索欄の Enter で, 使える部品のうち名前が一致するもの, 名前の終わりが一致するもの, 名前に含むもの, 説明に含むものの順に最初の 1 つを置く. 名前と説明のほかに, よく使う呼び方 (`global_mean_pool`, `dense`, `residual` など) でも探せる. 使えない部品の入れ方は `make setup EXTRAS=...` で示す
2. **キャンバス** (中央): ノード (部品), 入力, 出力を置き, 口から口へ線を引いてつなぐ. ノードには部品の名前, 口, 推定した出力の形, 誤りの印を出す (口の行にマウスを重ねると, 口の名前 (出力は形も) に登録簿の口の説明を付けて出す). 位置は定義の `ui` に保存する. 線とノードは選んで Delete か Backspace で消す. 幅の狭い画面ではミニマップを出さない
3. **詳細** (右): 選んだノードの名前, 入力のつなぎ先 (選択の欄. ノードは新しい順. 登録簿に口の説明 (`op.Reparameterize` の `mu` は「平均」など) があれば, 引数の説明と同じく欄の下に出し, 欄の説明として読み上げる), 引数のフォーム (登録簿の説明と範囲付き. 種類と範囲に合わない値はその場で理由を出して反映しない. 選択肢は選択の欄, 真偽値か null だけを受け取る引数 (`Optional[bool]`) は未設定, true, false, null の選択の欄, 値の候補 (`suggestions`) は打ちながら選ぶ欄), 一覧に無い引数 (`extra_params` の部品. 名前を書いて加える), 呼び出すときの設定の値, 入ってくる形 (つなぎ先ごと) と推定した出力の形とパラメータ数, 誤りと注意 (確認の誤りがあるノードは, 計算の誤りの文を重ねて出さない) を出す. 入力を選んだ場合は形, 型, 値の作り方を編集する. 何も選んでいない場合は全体の情報 (パラメータ数と学習するパラメータ数), 定義全体の誤り, 誤りと注意のあるノード (引数の不足, 出力に届かない, つなぎ先が 1 つの足し算など. 押すと選ぶ) と, 形の推定で失敗したノードと出力の一覧を出す
4. **上の操作**: 新規, 開く (保存した定義と同梱の例. 保存した定義は消せる. 例の説明は数行になる (雛形は学習の step で行うことまで書く) ので, 行の間を空けて全文を出す. 読み上げでは例の名前をボタンの名前, 説明をボタンの説明にする. 部分モデルにする一覧も同じ), 保存 (開いたものと違う名前で既にある定義に保存する場合は確かめる), 元に戻す・やり直す, 整列, 入力と出力の追加, YAML と Python のコードの表示 (コピーとファイルのダウンロード), 明るさの切り替え. 保存すると少しの間, 画面の右下に「<名前> に保存しました」と出す (誤りがあれば「誤り n 件のまま」も). 幅 1280 px 未満ではアプリの名前と, 新規, 開く, パラメータ数の文字を隠して (アイコンと数だけにして) 1 行に収める. 全体のパラメータ数と誤りの数 (形の推定の失敗を含む) を出し, 大きすぎて形を推定しない場合は「形は未推定」と出す. 幅が狭い画面では一部のボタンをアイコンだけにする

- **学習済みの重みのライセンス**: 学習済みの重みを読める部品 (ML-ModelControl の部品の一覧の `weights_params` が空でないもの. Hugging Face, timm, torchvision, segmentation_models_pytorch など) のノードの詳細に, 部品の説明の下に「学習済みの重みのライセンス」の欄を出す. ライセンスに関わる引数 (重みを読む引数と, モデルの名前, 版, 符号化器の名前と, 名前と版以外で重みを変える引数 (timm の `pretrained_cfg`, `pretrained_cfg_overlay`, `checkpoint_path` など. ML-ModelControl の `WEIGHT_OVERRIDE_PARAMS` に合わせる)) が落ち着いてから (0.6 秒) バックエンドに聞き (他の引数を変えても聞き直さない. 落ち着くまでの間は前の結果を出さず読んでいる途中と出す. ノードを選び直すと前のノードの結果は出さない), ML-ModelControl の `pretrained_info` が配布元 (Hugging Face のモデルの説明など) から読んだライセンス, 商用で使えるか, 説明, どこから読んだか (読めなかったか), 読んだ版, 推論の一式に重みを写せるか, 配布元のページへのリンクを出す. 商用で使えないものは誤りの色, 分からないもの (空, 独自の条件, 申請制, 読めなかった) は注意の色で「警告: …」とする (読み上げは控えめに `role="status"`. ノードを選ぶたびに割り込まないため). 重みを読まない引数 (`pretrained` を外すなど) では「今の引数では学習済みの重みを読みません」と出す. 部品の一覧では, 重みを読める部品の説明 (マウスを重ねた文) に, 置いた後の詳細でライセンスを確かめる案内を足す. 結果はバックエンドが覚え (読めたものは 1 日, 読めなかったものは 10 分), 画面も 10 分は聞き直さない. 非公開と申請制のモデルは, バックエンドを起動する環境の `HF_TOKEN` で読む. 通しのテスト (Playwright) は `HF_HUB_OFFLINE=1` で起動し, ネットワークを使わない
- **パラメータの状態 (定義の版 2)**: ノードの詳細の「呼び出すときの設定」の後に「パラメータの状態」の欄を出す (ML-ModelControl の定義の版 2 の `train`, `eval_mode`, `zero_init`, `weights`, `share`. 書き方と意味は ML-ModelControl の docs/DESIGN.md の「パラメータの状態」). 本体のノードと部分モデルの中のノードのどちらでも使える
    - 「学習する」(既定で入. 外すと `train: false` の凍結) と「評価の形のまま」(`eval_mode: true`. BatchNorm の統計と Dropout も止める. 凍結とは別に選び, 既定は外. 凍結した BatchNorm に書いていない場合は ML-ModelControl の注意 `frozen_norm_stats` を出す) のチェックの欄
    - 零初期化: 「しない」「全てのパラメータ」「名前を選ぶ」(カンマで区切った名前. 例: `weight, bias`. 部分モデルのノードは `nodes.fc.weight`)
    - 共有: 「しない」「ノード全体」(同じ部品のノードから選ぶ. 引数は同じ値を書く) 「パラメータごと」(1 行に `weight = embed.weight`). ノード全体を共有するノードは, 他の状態の欄を出さない (元のノードに従うため)
    - 外部の重み: 出どころ「読まない」「ファイル」(パス. 相対のパスは定義の置き場から) 「Hugging Face」(置き場の名前, ファイル, 版) 「学習済みの部品」(部品の名前と引数の JSON) と, 入れ物のキー (`state_key`), キーの付け替えの並び (1 行ごとに「前置き」か「正規表現 (番号の付け替え)」を選び, 前置き / 正規表現, 置き換え, 足す数 (正規表現だけ). 足す, 消す), 「合わない重みがあれば止める (strict. 既定で入)」のチェック. 既定の strict を欄の名前に出す
    - 「重みを読んで確かめる」ボタン: 定義全体を組み立てて外部の重みを実際に読み (`POST /api/weights`), 読んだノードごとに 読めた / 形の違う / 新しい / 使わない重みの数, 出どころ, ライセンス (Hugging Face と学習済みの部品から読んだ場合. 「学習済みの重みのライセンス」と同じ表示), 形の違うキーと新しいキーと使わないキーの一部を出す. 読めない場合 (ファイルが無い, strict で合わない, 1 つも読めない) は誤りの文を出す. ファイルとネットワークを使い, 重みも作るので, 編集のたびの確認 (`POST /api/check`) では読まず, ボタンを押したときだけ読む
    - 画面の中の定義は今の版 (2) で持ち, 版 2 の項目を使うと版を 2 にする (下書きや版 1 の空の定義に項目を足した場合). 保存と YAML の表示は ML-ModelControl の `dump_spec` が書ける最も低い版で書く (版 2 の項目を使わなければ版 1 のまま. 版 1 だけを読む古い学習のスクリプトでも読める)
    - 「ノード全体」の共有を選ぶと, 引数を元のノードに合わせ, 他の状態の項目を外す (元のノードに従うため). このノードを元に共有しているノードがある場合と, 同じ部品のノードが無い場合は選べない. 複製と写しでは `share` を写さない (別の定義に貼ると元のノードが違うため)
    - ノードの名前を変えると, 共有の元の名前 (`share` の値) も書き換える (同じ定義の中だけ. 外側のノードの `zero_init` や付け替えに書いた部分モデルの中の名前は書き換えない). 共有の元のノードを消すと, 共有の欄は残り誤り (`invalid_share`) になる (黙って共有を外さないため)
- **左右の欄**: 部品の一覧と詳細は, キャンバスの左上と右上のボタンで畳める. 幅 1200 px 未満の画面では畳んで始める. `/` で部品を探すと左の欄を開き, キーボードで部品を置くと詳細を開いて引数の最初の欄 (無ければ入力のつなぎ先) に移る
- 編集するたびに (少し待ってから) バックエンドで確認と形の推定をし, 結果をノードに重ねる
- キャンバスの線は定義の各ノードの `inputs` と 1 対 1 に変換する (可変の数の口は, 線を引いた順がリストの順)
- **元に戻す・やり直す** (Delete キーで消した線とノードは 1 回分. やり直しは Ctrl+Shift+Z か Ctrl+Y, Mac は Cmd): 定義を履歴付きの値で持つ (上限 100 回). 同じノードのドラッグの続けての移動は 1 回分にまとめ, 中身の同じ変更は残さない. 定義を開くか新規にすると履歴を消す. Ctrl+Z (Mac は Cmd+Z) と Ctrl+Shift+Z (か Ctrl+Y), 文字を打つ欄の中では, 打ちかけの文字がある間はブラウザの標準の取り消し, 値を反映した後 (打ちかけの文字が無い間) は定義を戻して欄にも出す
- **下書き**: 保存していない変更は, 少し待ってからブラウザ (`localStorage`) に画面 (タブ) ごとの下書きとして残す (書けない場合は古い下書きを残さないように消す). 次に開いたとき, その画面の下書き (無ければ他の画面の一番新しいもの. 14 日より古いものは出さない) を「保存していない定義の下書きがあります」と出し, 「下書きを開く」か「下書きを捨てる」を選べる (開くと保存していない変更として開く. 今の変更がある場合は確かめる). 保存する名前の欄に打った, まだ保存していない名前も下書きに残し, 開くと欄に戻す (下書きは定義の変更を守るためのもので, 名前だけを変えた場合は残さない. 新規, 開く, 保存で打った名前を消す. 保存の間は下書きを開く・捨てるを止める). 聞いている間は前の下書きを上書きしない. 保存, 新規, 開く, 捨てる, 保存した時点と同じに戻した場合に, その画面の下書きを消す
- **使えない部品の口**: ライブラリが無い部品と登録されていない部品のノードは, 定義のつなぎ先から口を推し量って (入力の口は inputs の名前, 出力の口は他から「ノード:口」で参照される名前) 線を描く (同梱の例をライブラリを入れずに開いても, つながりが見えるように)
- **置き場所と整列**: 新しく置くものは, 見えている範囲の真ん中の近くで他のノードと重ならない所に置く. 入力かノードを選んで部品を置くと, その右に置き (見えている範囲の外になる場合は, その位置に置いて表示を動かす), 置いた部品に必須の口か可変の数の口があれば, つなぎ元の最初の出力の口から最初の必須の口へ線を引く (出力が複数の部品も, 最初の口が主な出力 (`nn.MultiheadAttention` の `output`, `nn.LSTM` の `output` など). 参照は `ノード:口` になるので, 違えば詳細で選び直す. 以前は出力が複数の部品からは引かず, 自己注意の後に `op.Add` を置くと注意の出力がつながらないまま誤り 0 件になった). 他の口は, 同じ名前のモデルの入力 (GNN の `edge_index` など) があればそれにつなぐ. 出力を加えたとき, どこにもつながっていないノードが 1 つだけで出力の口が 1 つならそれにつなぐ. 置いた部品が選ばれるので, 続けて置くと一直線につながる (枝分かれさせる場合は, つなぎ元を選び直す). ノードの幅は整列の段の間隔に収まる上限 (236) までにし, 長い口の名前と形は省略してマウスを重ねると全体を出す. 整列 (後に全体が見えるように表示を合わせる) はつながりの深さで左から右へ段に分け (入力は最初, 出力は最後の段), 段が多い場合は折り返して下の行に続ける. 位置 (`ui`) の無い定義を開いた場合は, 位置の無いものにだけ同じ並べ方で位置を書く
- **読み上げと focus**: 先頭に「キャンバスへ移る」のリンク. ノードと線に日本語の読み上げの名前 (「ノード relu1 (nn.ReLU), 出力 out [4, 16]」「x から relu1 の input への線」). 明るさの切り替えは押した状態 (`aria-pressed`) を持つ. 詳細の欄の Esc は選んでいるノード (無ければキャンバス) に戻り, 消した後と Ctrl+S の後も focus を失わない. 全体のパラメータ数はマウスを重ねると正確な数
- **キーボード**: Ctrl+S (Mac は Cmd+S) で保存する (文字を打つ欄の中でも, 打ちかけの値を反映してから). Esc で編集している部分モデルから 1 つ上に戻る (押し続けても 1 つずつ). `/` で部品を探す欄に移る (Esc と `/` は文字を打つ欄の中では効かない)
- **複製と写し**: 選んだ部品のノードを引数ごと複製し (Ctrl+D), 写して貼れる (Ctrl+C, Ctrl+V. アプリの中だけ). つなぎ先は写さない

### 部分モデル

- **写す**: 部品の一覧の「別の定義を部品にする」で, 保存した定義か同梱の例を今の定義の `subgraphs` に写し (ML-ModelControl の部分モデル), 一覧の「部分モデル」から `sub.<名前>` の部品として置く. 写した定義の入力が入力の口, 出力が出力の口になる. 参照ではなく写すので, 元の定義を後で変えても変わらない. 今開いている定義自身は選べない. 誤りのある定義を写す場合は, 誤りの数と最初の誤りを出して写すかを確かめる (確認だけで形は推定しない). 写した結果 (付け直した名前など) と消した結果は一覧の上に知らせる
- **名前**: 写した定義の名前. 同じ名前で中身の同じものは 1 つにまとめ, 中身の違うもの, Python の予約語, 書き出すコードのクラスの名前 (本体の `Model` と他の部分モデル) と重なるものは番号などを付けた名前にする (写す定義の中の部分モデルも同じく付け直し, 中の `sub.<名前>` も直す). 中身の比較では写した元を除く (写した元だけが違う同じ中身は 1 つにまとめる)
- **写し直す**: 写した元 (保存した定義か例の名前) を部分モデルの `ui.source` に書き, 一覧の写し直しのボタンで, 同じ名前のまま元の定義の今の中身に置き換える (元の定義を直した後に. 元に戻すで戻せる). 口が変わった場合は本体の誤りになる. 前の中身の位置は同じ名前のものに残し, 位置だけの違いは変わっていない扱い. 前の中身だけが使っていて使われなくなった部分モデルは消す. 写す定義の中に同じ名前の部分モデルがあれば番号を付けた名前にして, 自分を使う形にしない. 読み込みの間に定義が変わった場合は, その時点の定義に対して行い, 部分モデルが無くなっていれば何もしない. 今開いている定義自身からは写し直さない
- **消す**: 使っているノードの無い部分モデルは一覧から消せる (他の部分モデルの中で使っている場合は, そちらを先に消すように知らせる)
- **中身を読む**: 選んだ部分モデルのノードの詳細で, 中身 (入力の元の形, 中のノードの部品と引数, 出力) を読める. 部分モデルの中の誤りは, 定義全体の誤りとして場所 (`subgraphs.<名前>...`) 付きで出す
- **中身を編集する**: 部分モデルを使うノードの詳細の「部分モデルの中身を編集」かノードのダブルクリックで, その部分モデルを 1 つの定義としてキャンバスで編集する. キャンバスの上に階層 (本体 › sub.outer › sub.block. 入れ子で開ける) と, 使っているノードの数を出し, 階層の名前で戻る. 変更は定義の中の部分モデルに書き戻し, 元に戻すの履歴は本体と同じ (戻して部分モデルが無くなった場合は, あるところまで戻る). 置くと循環になる部品 (自分自身と, 中で自分を使う部分モデル) は一覧に出さず, 貼り付けもしない. 位置の無い部分モデルは編集を始めるときに位置を書く (履歴に残さず, 保存していない変更にもしない). 保存, Python の書き出し, 別の定義を部品にする, 部分モデルを消す操作は定義全体に対して行い, YAML の表示は編集している部分モデルの中身を出す
- **編集している間の確認**: 確認と形の推定はその部分モデルだけで行う (自分自身を除き, 中で使う部分モデルだけを持たせる). 本体の部分モデルを開いた場合は, 本体も形の推定をして, その部分モデルを使うノードを計算の順に見て, 全ての入力の口の形が分かる最初のノードに入る形を入力の形にして推定する (入力から来る値は入力の型と値の作り方, ノードから来る値は出力の型と 0. 保存する入力の形は変えない. 「形はノード x に入る形で推定」と出す). そのようなノードが無い場合と入れ子で開いた場合 (本体は確認だけ) は, 部分モデルの入力に書いた形で推定する. 本体の誤り (口の名前を変えて本体のつなぎ先が合わなくなった場合など) も確かめて「本体に誤り n 件」と出す
- **ノードだけの部分モデル**: 部分モデルを使うノードの詳細の「このノードだけの部分モデルにする」で, その部分モデルを写して `<元の名前>_<ノード>` の部分モデルにし (2 つ以上のノードが使う部分モデルだけ), そのノードだけが使うようにする (同じ部分モデルを重ねた中の 1 段だけチャンネル数を変える場合など). 写したものは写し直しの対象にしない

## API

| 経路 | 内容 |
| --- | --- |
| `GET /api/units` | 部品の一覧 (ML-ModelControl の `describe_units`) |
| `POST /api/check` | 定義を確かめ, 誤りと注意, ノードごとの形とパラメータ数, 保存する形の YAML を返す (`validate` と `infer`. 形の推定をせずに確かめるだけにもできる) |
| `GET /api/examples`, `GET /api/examples/{name}` | ML-ModelControl に同梱した例のモデルの一覧と読み込み (「開く」から例を選んで編集を始める) |
| `GET /api/models` | 置き場の定義のファイルの一覧 |
| `GET /api/models/{name}` | 定義を読み込む |
| `PUT /api/models/{name}` | 定義を保存する |
| `DELETE /api/models/{name}` | 保存した定義を消す (名前が規則に合わない場合は 400, 無い場合は 404, 消せない場合は 500) |
| `POST /api/pretrained` | ノードの部品の名前と引数の値から, 学習済みの重みのライセンスの情報を返す (ML-ModelControl の `pretrained_info`. 重みを読まない場合は `null`, 登録簿に無い部品は 404). 配布元を読むのでネットワークを使う |
| `POST /api/weights` | 定義を組み立てて外部の重み (ノードの `weights`) を読み, ノードごとの報告 (読めた / 形の違う / 新しい / 使わない重みの数とキーの一部, 出どころ, ライセンス) を返す (ML-ModelControl の `build_model` と `weights_report`). 相対のパスは定義の置き場から (絶対のパスも読む. 定義の名前と違い置き場の中に限らない. 読むのは `torch.load` の `weights_only=True` と safetensors だけで, コードは動かさない). 外部の重みの無い定義は組み立てずに空の報告. 読み込みは 1 つずつ (途中なら待たずに知らせる). 読めない場合は `ok` が偽で誤りの文. ファイルとネットワークを使う |
| `POST /api/export` | 同じ計算をする Python のコードを書き出す (ML-ModelControl の `export_python`) |

- 定義のファイルの置き場は `~/.ml-createarchitecture/models/` (環境変数 `ML_CREATEARCHITECTURE_HOME` で変えられる). 名前はファイル名の規則 (英数字, `_`, `-`) に限り, 置き場の外には書かない
- 既定では `127.0.0.1` だけで待ち受ける (他のホストを指定すると警告を出す). 起動ごとのトークンを Cookie に保存したブラウザからだけ API を受け付ける (他のサイトから Hugging Face のモデルの取得などを起こされないように. ML-Dashboard と同じ仕組み)

## 課題の型への広げ方 (2026-11-18 の方針)

機械学習の課題は, 1 件の分からない値を当てる「予測する」(分類, 回帰, 時系列の予測. 検出, 領域分け, 文字起こし, 3D の形のような構造のある出力と, 正解のほぼ無い異常の検知も) のほかに, 正解が 1 つに決まらない中身を「作る」, 多くの候補から「並べる」(推薦, 検索), 正解の無いデータを「まとめる」(群分け), 行動の「効果を見積もる」(uplift, バンディットや強化学習の方策) に分けられる. 正解の出どころ (列, 対のファイル, 自分自身, 今の処理の出力, 行動の結果, 介入の記録, 指示 (プロンプト)), 1 件の単位 (行, まとまり, 対, 要求と候補, 窓), 作り方 (規則, 既製のモデルをそのまま, 頭だけ学習, 微調整, 一から) で, データの形と確かめ方が変わる (2026-11-18 に, モデルの系統と課題の事例を調べて決めた). 広げる順は, 約束 (ファイルの形の版) を変えずに出せるもの → 約束の版を上げるもの → 型ごとの通り道. 部品と定義の形は ML-ModelControl に足し, この画面はそれを使う.

- 受け持ちごとの雛形 (VAE, GAN の生成器と識別器, 拡散, 対照, 2 塔, 方策と価値) を開ける (済み. ML-ModelControl の同梱の例. 説明に学習の step で行うことを書き, 開くと誤り 0 件). それまでの例は全て予測 (主に分類) のモデル (BERT も分類の頭付き)
- ML-ModelControl の定義の版 2 に合わせ, ノードごとの「学習する / 凍結」「初期値 (零など)」「外部の重みとキーの付け替え」の欄と, 読み込みの数の報告 (読めた / 形の違う / 新しい / 使わない) (2026-11-20 に済み. 「画面」の「パラメータの状態」. 評価の形と重みの共有の欄も)
- 学習済みのモデルの部品に, ライセンス, 申請制か, 表示の義務を出す. 申請制の重みは取得に失敗しても理由を日本語で出す (ライセンスと申請制かは 2026-11-19 に済み. 「画面」の「学習済みの重みのライセンス」. 表示の義務はまだ)
- 研究の自作の部品を, 起動の設定で明示したモジュールから読み込んで置けるように
