# 設計

ML-CreateArchitecture の設計の方針をまとめる.

## 目的

ML-ModelControl の部品を GUI で並べてつなぎ, モデルを組み立てるローカルの Web アプリ.
コードを書かずに, 部品の一覧から選んで置き, 線でつなぎ, 引数をフォームで決め, 形とパラメータ数を確かめながらモデルの定義を作る.

- モデルの定義 (YAML か JSON) の読み書き, 確認, 形の推定, 組み立ては全て ML-ModelControl が行う. このアプリは画面と, 定義のファイルの置き場だけを受け持つ
- ML-ModelControl は submodule にする (ML-Dashboard と ML-Found の関係と同じ)
- 今は独立したアプリ. 将来は ML-Found と ML-Dashboard と合わせて, 1 つのアプリに統合することを目指す

## 構成

| 部分 | 中身 |
| --- | --- |
| バックエンド | Python, FastAPI. ML-ModelControl を呼ぶ API と, 定義のファイルの一覧, 読み込み, 保存 |
| 画面 | TypeScript, React, Vite. グラフの編集に React Flow (`@xyflow/react`) を使う |

ML-Dashboard と同じ構成と道具 (uv, pnpm, Ruff, mypy, Prettier, oxlint, OpenAPI から画面の型を作る) にそろえ, 将来の統合を楽にする.

## 画面

1. **部品の一覧** (左): 出どころと分類ごとに並べ, 名前と説明で検索する. 使えない部品 (ライブラリが無いものなど) は理由付きで選べない状態にする. ドラッグか押すことでキャンバスに置く
2. **キャンバス** (中央): ノード (部品), 入力, 出力を置き, 口から口へ線を引いてつなぐ. ノードには部品の名前, 口, 推定した出力の形, 誤りの印を出す. 位置は定義の `ui` に保存する
3. **詳細** (右): 選んだノードの名前, 入力のつなぎ先 (選択の欄. ノードは新しい順), 引数のフォーム (登録簿の説明と範囲付き. 種類と範囲に合わない値はその場で理由を出して反映しない. 選択肢は選択の欄, 値の候補 (`suggestions`) は打ちながら選ぶ欄), 一覧に無い引数 (`extra_params` の部品. 名前を書いて加える), 呼び出すときの設定の値, 入ってくる形 (つなぎ先ごと) と推定した出力の形とパラメータ数, 誤りと注意 (確認の誤りがあるノードは, 計算の誤りの文を重ねて出さない) を出す. 入力を選んだ場合は形, 型, 値の作り方を編集する. 何も選んでいない場合は全体の情報, 定義全体の誤りと, 形の推定で失敗したノードと出力の一覧を出す
4. **上の操作**: 新規, 開く (保存した定義と同梱の例. 保存した定義は消せる), 保存 (開いたものと違う名前で既にある定義に保存する場合は確かめる), 元に戻す・やり直す, 整列, 入力と出力の追加, YAML と Python のコードの表示. 全体のパラメータ数と誤りの数 (形の推定の失敗を含む) を出す. 幅が狭い画面では一部のボタンをアイコンだけにする

- 編集するたびに (少し待ってから) バックエンドで確認と形の推定をし, 結果をノードに重ねる
- キャンバスの線は定義の各ノードの `inputs` と 1 対 1 に変換する (可変の数の口は, 線を引いた順がリストの順)
- **元に戻す・やり直す**: 定義を履歴付きの値で持つ (上限 100 回). 同じノードのドラッグの続けての移動は 1 回分にまとめ, 中身の同じ変更は残さない. 定義を開くか新規にすると履歴を消す. Ctrl+Z (Mac は Cmd+Z) と Ctrl+Shift+Z, 文字を打つ欄の中ではブラウザの標準の取り消し
- **置き場所と整列**: 新しく置くものは, 見えている範囲の真ん中の近くで他のノードと重ならない所に置く. 入力かノードを選んで部品を置くと, その右に置き, つなぎ方が 1 通りに決まる場合 (つなぎ元の出力の口が 1 つで, 置いた部品に必須の口か可変の数の口がある) はそこから最初の必須の口へ線を引く. 出力を加えたとき, どこにもつながっていないノードが 1 つだけで出力の口が 1 つならそれにつなぐ. 置いた部品が選ばれるので, 続けて置くと一直線につながる (枝分かれさせる場合は, つなぎ元を選び直す). ノードの幅は整列の段の間隔に収まる上限 (236) までにし, 長い口の名前と形は省略してマウスを重ねると全体を出す. 整列はつながりの深さで左から右へ段に分け (入力は最初, 出力は最後の段), 段が多い場合は折り返して下の行に続ける. 位置 (`ui`) の無い定義を開いた場合は, 位置の無いものにだけ同じ並べ方で位置を書く
- **部分モデル**: 部品の一覧の「別の定義を部品にする」で, 保存した定義か同梱の例を今の定義の `subgraphs` に写し (ML-ModelControl の部分モデル), 一覧の「部分モデル」から `sub.<名前>` の部品として置く. 写した定義の入力が入力の口, 出力が出力の口になる. 参照ではなく写すので, 元の定義を後で変えても変わらない. 名前は写した定義の名前. 同じ名前で中身の同じものは 1 つにまとめ, 中身の違うもの, Python の予約語, 書き出すコードのクラスの名前 (本体の `Model` と他の部分モデル) と重なるものは番号などを付けた名前にする (写す定義の中の部分モデルも同じく付け直し, 中の `sub.<名前>` も直す). 写した結果 (付け直した名前など) と消した結果は一覧の上に知らせる. 誤りのある定義を写す場合は, 誤りの数と最初の誤りを出して写すかを確かめる (確認だけで形は推定しない). 写した元 (保存した定義か例の名前) を部分モデルの `ui.source` に書き, 一覧の写し直しのボタンで, 同じ名前のまま元の定義の今の中身に置き換えられる (元の定義を直した後に. 元に戻すで戻せる. 口が変わった場合は本体の誤りになる. 前の中身の位置は同じ名前のものに残し, 位置だけの違いは変わっていない扱い. 前の中身だけが使っていて使われなくなった部分モデルは消す. 写す定義の中に同じ名前の部分モデルがあれば番号を付けた名前にして, 自分を使う形にしない. 読み込みの間に定義が変わった場合は, その時点の定義に対して行い, 部分モデルが無くなっていれば何もしない. 今開いている定義自身からは写し直さない). 中身の比較では写した元を除く (写した元だけが違う同じ中身は 1 つにまとめる). 使っているノードの無い部分モデルは一覧から消せる (他の部分モデルの中で使っている場合は, そちらを先に消すように知らせる). 選んだ部分モデルのノードの詳細で, 中身 (入力の元の形, 中のノードの部品と引数, 出力) を読める. 部分モデルの中の誤りは, 定義全体の誤りとして場所 (`subgraphs.<名前>...`) 付きで出す. 部分モデルを使うノードの詳細の「部分モデルの中身を編集」かノードのダブルクリックで, その部分モデルを 1 つの定義としてキャンバスで編集できる. キャンバスの上に階層 (本体 › sub.outer › sub.block. 入れ子で開ける) と, 使っているノードの数を出し, 階層の名前で戻る. 変更は定義の中の部分モデルに書き戻し, 元に戻すの履歴は本体と同じ (戻して部分モデルが無くなった場合は, あるところまで戻る). 確認と形の推定はその部分モデルだけで行う (自分自身を除き, 中で使う部分モデルだけを持たせる). 本体の部分モデルを開いた場合は, 本体も形の推定をして, その部分モデルを使うノードを計算の順に見て, 全ての入力の口の形が分かる最初のノードに入る形を入力の形にして推定する (入力から来る値は入力の型と値の作り方, ノードから来る値は出力の型と 0. 保存する入力の形は変えない. 「形はノード x に入る形で推定」と出す). そのようなノードが無い場合と入れ子で開いた場合 (本体は確認だけ) は, 部分モデルの入力に書いた形で推定する. 本体の誤り (口の名前を変えて本体のつなぎ先が合わなくなった場合など) も確かめて「本体に誤り n 件」と出す. 保存, Python の書き出し, 別の定義を部品にする, 部分モデルを消す操作は定義全体に対して行う. 置くと循環になる部品 (自分自身と, 中で自分を使う部分モデル) は一覧に出さず, 貼り付けもしない. 位置の無い部分モデルは編集を始めるときに位置を書く (履歴に残さず, 保存していない変更にもしない)
- **ノードだけの部分モデル**: 部分モデルを使うノードの詳細の「このノードだけの部分モデルにする」で, その部分モデルを写して `<元の名前>_<ノード>` の部分モデルにし (2 つ以上のノードが使う部分モデルだけ), そのノードだけが使うようにする (同じ部分モデルを重ねた中の 1 段だけチャンネル数を変える場合など). 写したものは写し直しの対象にしない
- **キーボード**: Esc で編集している部分モデルから 1 つ上に戻る (選んでいるものがある場合は, まず選択を外す. 押し続けても 1 つずつ). `/` で部品を探す欄に移る (文字を打つ欄の中では効かない)
- **複製と写し**: 選んだ部品のノードを引数ごと複製し (Ctrl+D), 写して貼れる (Ctrl+C, Ctrl+V. アプリの中だけ). つなぎ先は写さない

## API

| 経路 | 内容 |
| --- | --- |
| `GET /api/units` | 部品の一覧 (ML-ModelControl の `describe_units`) |
| `POST /api/check` | 定義を確かめ, 誤りと注意, ノードごとの形とパラメータ数を返す (`validate` と `infer`) |
| `GET /api/examples`, `GET /api/examples/{name}` | ML-ModelControl に同梱した例のモデルの一覧と読み込み (「開く」から例を選んで編集を始める) |
| `GET /api/models` | 置き場の定義のファイルの一覧 |
| `GET /api/models/{name}` | 定義を読み込む |
| `PUT /api/models/{name}` | 定義を保存する |
| `DELETE /api/models/{name}` | 保存した定義を消す (無い場合は 404, 消せない場合は 500) |
| `POST /api/export` | 同じ計算をする Python のコードを書き出す (ML-ModelControl の `export_python`) |

- 定義のファイルの置き場は `~/.ml-createarchitecture/models/` (環境変数 `ML_CREATEARCHITECTURE_HOME` で変えられる). 名前はファイル名の規則 (英数字, `_`, `-`) に限り, 置き場の外には書かない
- `127.0.0.1` だけで待ち受ける. 起動ごとのトークンを Cookie に保存したブラウザからだけ API を受け付ける (他のサイトから Hugging Face のモデルの取得などを起こされないように. ML-Dashboard と同じ仕組み)

## 段階

| 段階 | 内容 |
| --- | --- |
| 1 | バックエンド (部品の一覧, 確認と形の推定, 定義の保存) と, キャンバスで部品を置いてつなぎ, 引数を決めて保存できる画面 |
| 2 | 形とパラメータ数をノードに重ねる表示, 誤りの印, YAML の表示 |
| 3 | Python のコードの書き出し (済み), 元に戻す, 整列, 複製などの編集の操作 (済み), ML-Found のプロジェクトへの書き出し (今は ML-ModelControl の README の手順で, 保存した定義を学習スクリプトから組み立てる) |
